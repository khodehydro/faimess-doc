# FAIMESS

داشبورد وب **FAIMESS** — بازسازیِ دقیق صفحهٔ Home از طراحی مرجع، با معماری ماژولار.
**Vite + React 19 + TypeScript + Tailwind CSS v4 + Framer Motion** — همهٔ تصویرها داخل خود اپ سرو می‌شوند: **عکس‌های واقعی self-hosted** (آرتیست، کاور، پلی‌لیست، شنونده، بنر) به‌همراه تصویرسازی برداری به‌عنوان fallback و برای کارت‌های خبر.
کارت سمت راست یک **پلیر** است، نه چت‌باکس: کاور، نوار پیشرفت، کنترل پخش و **لیریک دوزبانهٔ همگام** (متن اصلی + ترجمهٔ فارسی).

---

## اجرا

```bash
npm install
npm run dev        # → http://localhost:5173
npm run build      # بیلد پروداکشن (tsc + vite)
npm run preview    # سرو بیلد
```

## موبایل و تبلت (پوستهٔ کامپکت)

زیر **۱۰۲۴px** (یعنی موبایل و تبلت) اپ از حالت «آرت‌بورد مقیاس‌شده» بیرون می‌آید و
همان پنج تکه را برای دست می‌چیند:

- **بالا:** اعلان در چپ، لوگو + FAIMESS دقیقاً وسط، و پروفایل در راست.
- **زیر آن:** **جست‌وجو در یک کپسول جداگانهٔ تمام‌عرض** — `rounded-full`، پس دو سرِ کارت
  دقیقاً نیم‌دایره است (همان شکلِ پیل دسکتاپ، تنها در یک کارت مستقل).
- **بین سرچ و بنر:** **ریلِ استوریِ آرتیست‌های دنبال‌شده** (`ArtistStories`) — بیرون از کارت
  محتوا، در بخش جداگانهٔ خودش. هر خانه فقط **عکس دایره‌ای + نام** است: بدون تیتر، بدون
  شمارنده، بدون دکمهٔ «Find artists»، بدون نشان و آیکن. حلقهٔ دور عکس برای آرتیستی که
  انتشار تازه دارد **گرادیان بنفش→فیروزه‌ای** است و برای بقیه خنثی — همان «دیده‌نشده/دیده‌شده»ی
  استوری، تا چیزی روی عکس ننشیند. ریل افقی اسکرول می‌شود و کلیک روی هر خانه کارتِ همان
  آرتیست را باز می‌کند. این ریل فقط روی **Home** است (جایی که بنر هست).
- به همان دلیل، **شلف «Artists you follow» در موبایل و تبلت از فید حذف می‌شود**
  (`compactHidden` در `FEED_SHELVES`) تا یک فهرست دو بار روی صفحه نیاید؛ روی دسکتاپ همان
  شلف سر جایش است.
- **منوی اصلی در پایین می‌چسبد** (`MobileNav`) — یک کپسول سفیدِ نیمه‌شفاف با همان
  نشانِ تب فعال: آیکن و متن بنفش + خط بنفش زیرش.
- **مینی‌پلیر بنفش** فقط بعد از انتخاب/پخش یک آهنگ ظاهر می‌شود؛ از زیر نویگیشن بالا می‌آید
  و زیر لایهٔ منو می‌نشیند (کاور، نام، پخش/توقف، بعدی؛ بدون نوار وضعیت/پیشرفت). کلیک روی
  آن **صفحهٔ کامل پلیر** را باز می‌کند — همان کارت پلیر دسکتاپ، نه یک نسخهٔ جداگانه.
- **شلف «جدیدترین آهنگ‌ها» زیر ۱۰۲۴px دیگر لیست نیست:** یک **گرید سه‌ستونه از
  کاورهای مربع با گوشهٔ گرد** است (۶ آهنگ = ۲ ردیف کوتاه). روی هر کاور فقط برچسب
  «تازه» می‌نشیند و زیر آن نام آهنگ و آرتیست؛ مدت آهنگ و زمان انتشار («۲ ساعت پیش»)
  luxuryِ ردیف دسکتاپ‌اند و در کارت موبایل جا نمی‌شوند. روی دسکتاپ همان دو ستون
  ردیف پهن با کاور ۴۴px برمی‌گردد.
- **هدر کامپکت یک گرید `1fr auto 1fr` است** — لوگو روی محور وسط می‌نشیند و اعلان و
  پروفایل به دو لبه می‌چسبند و عمودی وسط‌چین‌اند. پیل مطلقِ قبلی نسبت به *جعبهٔ* والد
  وسط‌چین می‌شد، و چون دو کنترل هم‌اندازه نیستند، واژه‌نشان به‌اندازهٔ نصف اختلافشان از
  مرکز بیرون می‌زد.
- **زنگ اعلان حول محور خودش می‌چرخد** (`transform-box: fill-box` + `transform-origin:
  top center`) — بدون آن `rotate()` آیکن را دور گوشهٔ viewBox می‌چرخاند و از دایرهٔ
  دکمه بیرون می‌زد؛ بقیهٔ آیکن‌های متحرک در `index.css` از قبل همین را داشتند.
- **ریل «فعال‌ترین شنوندگان» بالای کارت‌ها `pt-2` دارد:** روی لمسی، تپِ کارت حالت
  `whileHover` را هم فعال می‌کند و کارت ۴px بالا می‌آید؛ در ریلِ هم‌قد، همان ۴px از
  لبهٔ بالا بریده می‌شد و ریبون رتبه ناقص دیده می‌شد.
- **هدر شلف روی موبایل و تبلت یک‌ردیفه می‌ماند:** آیکن و عنوان و توضیح در سمت شروع،
  اکشن (مثل «پخش همه» یا سوییچ ۲۴ ساعت/هفته) با `ms-auto` و `shrink-0` در سمت پایان.
  بخش کشسان همان عنوان است و ترانکیت می‌شود؛ دکمه هرگز به خط بعد نمی‌افتد.
- **اندازه‌ها زیر ۱۰۲۴px یک پله کوچک‌تر می‌شوند** و روی دسکتاپ (`lg:`) به مقدار اصلی
  برمی‌گردند: بنر خانه ۲۱۰px (به‌جای ۳۴۰px) با تیتر ۱۹px، عنوان صفحه‌ها ۱۹px (به‌جای
  ۲۶px)، تیتر شلف ۱۵.۵px، ردیف آهنگ با کاور ۴۰px و متن ۱۳.۵px، کاور کارت‌ها و
  پلی‌لیست ۵۸–۷۲px و پیل‌ها با پدینگ کمتر. هدف این است که محتوا در نگاه اول جا شود،
  نه اینکه با اسکرول افقی یا شکستن خط کشیده شود.
- **نوار «followed / new songs / …» در موبایل و تبلت نمایش داده نمی‌شود**؛ شلف‌ها
  ساده اسکرول می‌شوند.
- **هیچ اسکرولِ افقی اسکرول‌بار ندارد:** ریلِ استوری، شلف‌های فید، نوار چیپ‌ها، ردیفِ
  «پلی‌لیست‌های من» و جدولِ رتبه‌بندی همه `scroll-rail`‌اند — روی لمس (و زیر ۱۰۲۴px) کاملاً
  بی‌میله، چون اندروید میلهٔ خودش را روی عکس‌ها می‌کشد؛ روی دسکتاپ همان میلهٔ نازکِ قبل می‌ماند.
  اسکرولرهای **عمودی** عمداً `scroll-slim` ماندند (میلهٔ عمودی می‌گوید «زیرش هم هست»).

مرز ۱۰۲۴px یک عدد است، نه دو تا: هم `useCompact()` و هم `useStageScale` از همان خط
می‌خوانند تا هیچ‌وقت با هم اختلاف پیدا نکنند.

## زبان و فارسی‌سازی

هر رشتهٔ رابط در یک جدول تخت (`src/data/i18n.ts`) است: `en` منبع حقیقت، `fa` و `ko`
ترجمه‌ها. سه در برای متن وجود دارد:

| ابزار | برای چه چیزی | نمونه |
| --- | --- | --- |
| `t(key, vars)` | رشته‌های خود رابط | `t("shelf.playAll")` |
| `dataLabel(value)` | **برچسب‌هایی که در فایل‌های داده انگلیسی مانده‌اند** — kind، genre، mood، `4.8M monthly`، `2 hrs ago`، `3h 12m`، تگ و منبع خبر، `Lv`/streak، `· single`، ساعت و تاریخ چت | `dataLabel(artist.listeners)` → «۴٫۸ میلیون شنوندهٔ ماهانه» |
| `text(key, fallback)` | **کپی تحریریه** که منبعش در داده است ولی مال پلتفرم است، نه کاربر (اسلاید بنر، تیتر و لید خبر) | <code>text(\`banner.id.title\`, banner.title)</code> |
| `num(value)` | عدد خالی، با ارقام و جداکنندهٔ همان زبان | `num(album.year)` → ۲۰۲۵ |

- **ارقام فارسی:** هر عددی که به `t` پاس داده شود خودکار به ۰–۹ فارسی تبدیل می‌شود، و
  `tData` واحدها را هم برمی‌گرداند («۱۸٫۴ هزار»، «۲۴ ساعت پیش»).
- **بدون نشتی انگلیسی:** برچسب داده‌ای که از `tData` رد نشود در جایی چاپ نمی‌شود — یک
  چک SSR روی همهٔ سورس‌ها همین را قفل می‌کند (`no page prints a data label in English`).
- **چه چیزی انگلیسی می‌ماند؟** محتوای دمو: نام آرتیست/آلبوم/ترک، متن کامنت، بدنهٔ لیریک و
  نام محصولات فروشگاه — اینها محتوایند، نه رابط، و مثل لیریک دوزبانه دست‌نخورده می‌مانند.

## تست روی گوشی (همان Wi-Fi)

دِو سرور روی `0.0.0.0` گوش می‌دهد (`vite.config.ts`)، پس گوشیِ متصل به همان شبکه
می‌تواند سایت را باز کند:

```powershell
ipconfig                     # IPv4 آداپتور Wi-Fi را بردار، مثلاً 192.168.1.42
npm run dev                  # خط «Network:» خودش همان آدرس را چاپ می‌کند
npm run dev -- --open        # یا با باز شدن مرورگر خودِ PC
```

بعد روی گوشی: `http://192.168.1.42:5173` (نه `localhost`).

- **فایروال ویندوز:** بار اول پیام Windows Defender می‌آید → گزینهٔ **Private networks**
  را تیک بزن و Allow کن. اگر رد کردی، در PowerShellِ **Run as Administrator**:
  `New-NetFirewallRule -DisplayName "Vite dev (5173)" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 5173 -Profile Private`
- **HMR روی گوشی:** سوکت زندهٔ Vite از پورت خودِ صفحه استفاده می‌کند (`VITE_HMR_PORT`
  خالی) تا `ws://192.168.x.x:5173` وصل شود. فقط پیش‌نمایش میزبانی‌شده که پشت https روی
  ۴۴۳ پروکسی می‌شود آن را پین می‌کند: `VITE_HMR_PORT=443 npm run dev`.
- **تست بیلدِ پروداکشن روی گوشی:** `npm run build` و بعد `npm run preview` →
  `http://192.168.1.42:4173` (این پورت هم روی `0.0.0.0` تنظیم شده).
- **اگر باز نشد:** آداپتور اشتباه (WSL/Hyper-V/VirtualBox هم IPv4 دارند — آنِ Wi-Fi را
  بردار)، «AP/Client isolation» در روتر (خصوصاً Wi-Fi مهمان)، یا VPN روی PC.

## نکتهٔ کلیدی طراحی: «صحنه» (Stage) و بدون اسکرول

کل رابط دسکتاپ روی یک **آرت‌بورد ثابت ۱۵۸۰×۸۸۹** (نسبت ۱۶:۹) کشیده می‌شود (`src/lib/stage.ts`) و این صحنه به‌صورت **یکنواخت (scale)** به اندازهٔ پنجره بزرگ/کوچک می‌شود:

```
scale = min((vw − 40) / 1580 , (vh − 40) / 889 , 1.5)
```

نسبت بورد دقیقاً ۱۶:۹ است، پس در نمایشگرهای دسکتاپ هر دو محور همزمان پر می‌شوند و فاصلهٔ کنارها **دقیقاً ≈۲۰px** می‌ماند.

نتیجه: در هر ابعاد دسکتاپی، ترکیب صفحه **هیچ‌وقت جابه‌جا یا اسکرول نمی‌شود** — فقط بزرگ و کوچک می‌شود. (زیر ۱۰۲۴px اسکیل غیرفعال و چیدمان تک‌ستونی و اسکرول‌دار می‌شود.)

### نردبان رنگ سطح‌ها

| لایه | رنگ | نقش |
|---|---|---|
| بوم (studio backdrop) | `#EAEAEC` | پس‌زمینهٔ بیرونی صحنه |
| **کارت والد (shell)** | **`#F1F2F5`** | نگه‌دارندهٔ هر پنج کارت — روشن‌تر از بوم، عمیق‌تر از کارت‌های سفید |
| کارت‌ها | `#FFFFFF` | پیل‌های بالایی و دو کارت محتوا |

به‌این‌ترتیب هر لایه از دو لایهٔ دیگر قابل تفکیک است. توکن‌ها: `bg-shell` و `rounded-shell` (شعاع ۳۰px) در `src/index.css`.

### ساختار پنج‌کارتی داخل کارت والد (مطابق تصویر مرجع)
همهٔ کارت‌ها **درون یک کارت والد** `#F1F2F5` قرار گرفته‌اند و پنج کارت مستقل داخل آن شناورند:

| کارت | شکل | محتوا |
|---|---|---|
| ۱. برند | **پیل (دو سر نیم‌دایره)** | لوگو + وردمارک FAIMESS |
| ۲. منوی اصلی | **پیل** | Home / Artists / Albums / Playlists — تب فعال **بنفش** (آیکن + متن) بدون هیچ پس‌زمینه‌ای، و چون این نوار بالای همه‌چیز است **خط زیرش نیست** |
| ۳. سرچ + اعلان + پروفایل | **پیل** | فیلد جست‌وجو، زنگ، آواتار (پاپ‌اورها زیرش باز می‌شوند) |
| ۴. کارت چپ | `rounded-card` (۲۲px) | بنر + فید موسیقی — **۷۵٪ عرض** (یک سطح اسکرول مشترک) |
| ۵. کارت راست | `rounded-card` (۲۲px) | **پلیر** — ۴۰٪ مشخصات آهنگ + ۶۰٪ لیریک دوزبانه — **۲۵٪ عرض** |

سه کارت بالایی با `rounded-full` ساخته شده‌اند تا **چپ و راست هر کارت دقیقاً نیم‌دایره** شود؛ دو کارت محتوا گردی معمولی کارت را دارند. کارت والد با `rounded-shell` (۳۰px) و `shadow-frame` از بوم جدا می‌شود.

### ستون‌ها
- **چپ (بنر + فید موسیقی):** `flex-1` — با عرض فریم کشیده می‌شود.
- **راست (پلیر):** **۲۵٪** عرض ردیف (`home-split-right`) — ۴۰٪ بالای کارت مشخصات آهنگ، ۶۰٪ پایین لیریک (تنها سطح اسکرول این کارت).
- **کل ستون چپ یک سطح اسکرول واحد است:** بنر و فید با هم اسکرول می‌شوند، پس بنر با پایین‌رفتن طبیعی از دید خارج می‌شود (نه اینکه ثابت بماند). اسکرول‌بار متعلق به ستون است، نه به باکس فید.
- ارتفاع‌ها: کارت والد کل صحنه (۱۵۸۰×۸۸۹) را می‌گیرد و ۱۴px پدینگ دارد؛ ردیف پیل‌ها ۶۲px، هیرو ۳۴۰ و خوش‌آمد ۳۲۰ درون کارت‌ها.
- با اسکرول، **نوار چیپ‌ها** به لبهٔ بالای ستون می‌چسبد و **هدر هر شلف** دقیقاً زیر آن (۴۸px) می‌ماند تا همیشه بدانی کجایی. تب فعال این نوار (که خودش زیر محتوایی است که عوض می‌کند) **بنفش** است و یک **خط بنفش زیرش** کشیده می‌شود؛ همین خط با انیمیشن بین تب‌ها سُر می‌خورد.

نکتهٔ فنی: چون صحنه `transform: scale()` دارد، مختصات اشاره‌گر با `transformPagePoint` در `MotionConfig` تصحیح می‌شود تا درگ و هاور دقیقاً ۱:۱ بماند.

## معماری ماژولار

```
src/
├── app/
│   ├── App.tsx          قاب اصلی + مسیریابی صفحه‌ها + ترنزیشن بین صفحه‌ها
│   ├── Stage.tsx        مقیاس‌دهی صحنه + تصحیح مختصات اشاره‌گر
│   ├── AppContext.tsx   کانتکست مشترک: route / navigate / notify (toast)
│   ├── PlayerContext.tsx  حالت پخش: ترک فعلی · play/pause/next/prev/seek · صدای واقعی
│   ├── CommentsContext.tsx  ترد کامنت هر ترک: ارسال · ریپلای · فایر · گزارش · حذف
│   ├── ContributionsContext.tsx  شیت‌های لیریکی که کاربران می‌فرستند: pending · تأیید · امتیاز
│   ├── router.ts        روتر hash مینیمال (بدون وابستگی) — Home/Artists/Albums/Playlists
│   └── ToastHost.tsx    نمایش اعلان‌های گذرا
├── sections/            ← همهٔ بخش‌ها اینجا؛ هر بخش یک ماژول مستقل
│   ├── registry.tsx     رجیستری بخش‌ها (نقطهٔ توسعه)
│   ├── BrandCard.tsx    کارت ۱ — پیل برند
│   ├── NavCard.tsx      کارت ۲ — پیل منوی اصلی
│   ├── AccountCard.tsx  کارت ۳ — پیل سرچ/اعلان/پروفایل
│   ├── PlayerSection.tsx  کارت ۵ — پلیر (TrackPanel ۴۰٪ + LyricsPanel ۶۰٪ + نوار کامنت)
│   ├── player/            CommentsBar · CommentComposer · CommentsSheet · SubmitLyrics (فرم ارسال لیریک)
│   ├── ContributionsModal.tsx  «Your contributions» — ارسال‌ها، امتیاز، اکشن مدیر
│   ├── GreetingSection.tsx · MessagesSection.tsx   (در رجیستری می‌مانند، روی Home سوار نیستند)
│   ├── HeroBanner.tsx   بنر چرخشی با دکمه‌های قبلی/بعدی
│   ├── ArtistStories.tsx  ریل استوری آرتیست‌های دنبال‌شده — فقط کامپکت، بین سرچ و بنر
│   ├── ScheduleSection.tsx     (آماده برای صفحات دیگر)
│   ├── feed/                   فید موسیقی خانه — شش شلف مستقل + Shelf مشترک
│   │   ├── index.tsx           FEED_SHELVES: ترتیب/افزودن/حذف شلف در یک خط (+ `compactHidden`)
│   │   ├── Shelf.tsx           هدر چسبان + ردیف افقی + دکمهٔ پخش
│   │   ├── FollowedArtists.tsx آرتیست‌های فالو‌شده (کاور دایره‌ای + نام) — فقط دسکتاپ
```

### افزودن بخش جدید (۳ خط)
1. فایل بخش را در `src/sections/` بساز (مثلاً `PlayerSection.tsx`) — ورودی‌اش `{ params }`.
2. در `registry.tsx` یک کلید به `SectionParams` و یک خط به `sections` اضافه کن.
3. در هر صفحه‌ای که لازم است: `<SectionSlot id="player" params={...} />`.

### افزودن شلف به فید خانه
یک کامپوننت در `src/sections/feed/` بساز (داخلش از `Shelf` استفاده کن) و یک خط به آرایهٔ `FEED_SHELVES` در `src/sections/feed/index.tsx` اضافه کن — همین. ترتیب آرایه = ترتیب نمایش، و چیپ میان‌بر بالای باکس خودکار ساخته می‌شود.

### افزودن بنر جدید
یک آبجکت به `src/data/banners.ts` اضافه کن (عنوان، تاریخ، مکان، شمارندهٔ «going»، مسیر عکس
و سه ایستگاه) و دو کلید `banner.<id>.title` / `banner.<id>.subtitle` را در `src/data/i18n.ts`
قرار بده — بنر کپی تحریریه است و باید به زبان رابط بخواند (رجوع کن به بخش «زبان و
فارسی‌سازی»). به همین ترتیب برای خبر تازه در `src/data/feed.ts` کلیدهای
`news.<id>.title` و `news.<id>.excerpt`.

### افزودن صفحهٔ جدید
یک کلید در `app/router.ts` + یک کامپوننت در `pages/` + یک خط در `PAGES` داخل `app/App.tsx`. اگر می‌خواهی در منو **نباشد** ولی از داخل اپ قابل رفتن باشد (مثل صفحهٔ `News`)، آن را به `contextualRoutes` اضافه کن.

## پلیر (کارت ۵)

کارت سمت راست دیگر چت‌باکس نیست؛ یک **پلیر** است:

- **دکمهٔ more (⋯) و سایدبار مدیریت موسیقی:** ریل به‌صورت پیش‌فرض **بسته** است تا لیریک تمام عرض کارت را بگیرد؛ کلیک روی `⋯` در هدر کارت آن را باز می‌کند (انیمیشن عرض ۴۶px، `inert` وقتی بسته است) با سه تب — `Up next` (کل صف با شماره، کاور، مدت و پخش با یک کلیک، ترک در حال پخش هایلایت)، `Liked songs` (با دکمهٔ ♥ روی نوار پخش پر می‌شود) و `Playlists` (شش لیست ادیتوریال → صفحهٔ Playlists). بستن ریل، پنل باز را هم می‌بندد.
- **۴۰٪ بالا — مشخصات آهنگ:** کاور، نام ترک، آرتیست و آلبوم، نوار پیشرفت (کلیک/درگ + کلید ←/→، با `role="slider"` و `aria-valuetext`) و ردیف کنترل‌ها به‌صورت **آینه**: ♥ سمت چپ، قبلی/پخش/بعدی وسط، ⤓ دانلود سمت راست (هم‌اندازه و هم‌شکلِ ♥).
- **♥ لایک:** وقتی آهنگ لایک می‌شود هم پیل بنفش پشت دکمه روشن می‌شود و هم **خودِ قلب پُر می‌شود** — پک دو کات از یک قلب دارد (`favorite` خطی و `favorite-fill` پُر) و دکمه با `aria-pressed` جابه‌جا می‌کندشان؛ پس فقط رنگ عوض نمی‌شود، شکل عوض می‌شود.
- **اگزپند / کولپس:** دکمهٔ گوشهٔ هدر کارت را بین دو حالت می‌برد — باریک (۲۵٪، حالت پیش‌فرض) و باز (**۵۵٪**؛ کارت چپ به ۴۵٪ می‌رسد) با انیمیشن ۴۲۰ms؛ در حالت باز کاور و تیتر آهنگ هم بزرگ‌تر می‌شوند.
- **صدای واقعی:** یک مستر دموی ۲:۴۰ در `src/assets/audio/faimess-demo.mp3` — پخش/توقف/بعدی/قبلی/درگ نوار پیشرفت روی همین فایل کار می‌کنند (جزئیات: [`docs/audio.md`](docs/audio.md)).
- **۶۰٪ پایین — لیریک دوزبانه:** هر خط متن اصلی (کره‌ای/انگلیسی) و زیرش **ترجمهٔ فارسی RTL**؛ خط در حال پخش هایلایت می‌شود و اسکرول خودکار آن را وسط نگه می‌دارد (اگر خودت اسکرول نکرده باشی). این ناحیه **تنها سطح اسکرول کارت** است.
- **حالت خالی:** تا آهنگی انتخاب نشده، کارت با 👋 سلام می‌دهد — «Hey Sori, nothing playing yet» + «یه آهنگ که دوست داری رو پخش کن 🎧» — و سه پیشنهاد سریع برای شروع.
- **دکمهٔ دانلود (دانلود در وب نداریم):** دقیقاً هم‌شکل و هم‌رنگ ♥ (تک‌رنگ، بدون رنگ دومی) و کلیک روی آن یک **دیالوگ** باز می‌کند: «Downloads live in the Android app» + دکمهٔ **Android download page** که به صفحهٔ `#/download` می‌برد (و «Not now» برای بستن). هیچ فایلی در وب ذخیره نمی‌شود.

## کامنت‌ها (پایین کارت راست)

پایین کارت پلیر یک نوار کامنت نشسته است و زیر آن گفت‌وگو کامل باز می‌شود:

- **باکس ارسال کامنت:** آواتار خودت (با نشان آخرین جایزه‌ات) + اینپوت + دکمهٔ ارسال؛ `Enter` می‌فرستد، `Escape` انصراف، شمارندهٔ ۲۴۰ کاراکتر، و متن با `dir="auto"` رندر می‌شود تا کامنت فارسی درست راست‌چین بیفتد.
- **نمای تیزر:** تازه‌ترین کامنت + تعداد ریپلای‌های انجمن، و دکمهٔ **See all** (بالای نوار) که گفت‌وگوی کامل را باز می‌کند.
- **شیت کامنت‌ها:** هدر با تعداد + سورت (`Newest` / `Top fired`)، ترد ریپلای‌ها (نمایش/مخفی)، دکمهٔ **Load N more comments** و در انتها پیام «همهٔ کامنت‌های این بیلد دمو». کامنت خود آرتیست فقط با تینت بنفش (`bg-primary-faint/50`) جدا می‌شود — **پین نداریم**، چون آرتیست خودش داخل سایت نیست که کامنتی را بالا نگه دارد.
- **ریپلای و بحث:** زیر هر کامنت دکمهٔ Reply → باکس ریپلای درجا (`Reply to @handle…`)، ریپلای‌ها تودرتو با خط راهنما، و پاسخ‌های خود آرتیست با حلقهٔ بنفش + بج `ARTIST`.
- **گزارش:** منوی ⋯ هر کامنت → `Report comment` → خود شیت به حالت گزارش می‌رود (۵ دلیل: Spam / Harassment / Spoiler / Misinformation / Something else) → ثبت = کامنت به‌شکل «Hidden — you reported this as …» جمع می‌شود با دکمهٔ **Undo**.
- **نشان کاربران:** هر آواتار می‌تواند کرستِ **آخرین جایزه** را گوشه‌اش داشته باشد (👑 Top listener · Season 12، 📈 Weekly chart #1، ⭐ Fan of the month، ⚡ 30-day streak، 🏅 Community moderator، ✨ Rookie of the week) — با tooltip و چیپ برچسب کنار نام.
- **بقیهٔ موارد:** فایر/لایک روی کامنت و ریپلای (با انیمیشن و شمارنده)، منوی ⋯ (`Reply` / `Copy link` / `Report` / `Delete` برای کامنت خودت)، کارت خالی «No comments yet»، و بسته‌شدن با Esc یا کلیک روی پس‌زمینه.

## لیریک‌های کاربران (ارسال · تأیید مدیریت · امتیاز)

ترکی که شیت ندارد، در پنل لیریک یک بلوک **وسط‌چین** می‌گیرد: بج میکروفون،
«No lyrics for this one yet»، متن راهنما، دکمهٔ «Send the lyrics» و خط پاداش
(+۱۲۰ امتیاز). فارسی همان را آینه می‌کند و هر دو خط پاداش و دکمه کامل دیده
می‌شوند. برای این‌که این حالت یک کلیک از خانه فاصله داشته باشد، تازه‌ترین ردیف
شلف Newest (ترک `Afterimage` از NOVAE) عمداً بی‌شیت است — همان ترکی که با
کلیک روی «Send the lyrics» فرم ارسال شیت را باز می‌کند.


هر ترکی لیریک ندارد، پنل لیریک خودش دعوت‌نامه می‌شود:

- **حالت خالی:** آیکن میکروفن + «No lyrics for this one yet» + یک خط توضیح + دکمهٔ بنفش **Send the lyrics** و خط «Approved sheets pay +120 fan points». اگر همان کاربر قبلاً شیت فرستاده باشد، جای دکمه پیام «Pending review» با آیکن ساعت می‌نشیند.
- **فرم ارسال (`SubmitLyrics`):** زبان متن اصلی (한국어 / English / Mixed)، متن لیریک (هر خط یک خط؛ تایم‌استمپ `[01:12]` اختیاری) و ترجمهٔ فارسی اختیاری. اعتبارسنجی با `submissionProblem`: حداقل ۲ خط و ۲۴ کاراکتر؛ تا آن حد دکمه غیرفعال و دلیلش زیر فرم نوشته می‌شود.
- **بعد از ارسال:** مودال حالت «Sent to the moderators» می‌گیرد، توست «Lyrics sent for review — +120 pts once approved» می‌آید و ارسال با وضعیت **Pending review** ثبت می‌شود.
- **تأیید از سمت مدیریت:** بیلد ادمین‌کنسول ندارد؛ `ContributionsContext` دو اکشن `approve(id)` / `reject(id)` دارد که نقش میز تحریریه را بازی می‌کنند و از پنل **Your contributions** (پاپ‌آور پروفایل، کارت ۳) در دسترس‌اند. با **Approve**: امتیاز به حساب اضافه می‌شود (توست `Sheet approved — +120 points`)، متن به‌عنوان لیریک همان ترک منتشر می‌شود (با تایم‌های پخش‌شده در طول ترک) و زیر هدر لیریک خط اعتبار «Fan sheet by you · approved by the mods · +120 pts» می‌آید.
- **امتیاز در پروفایل:** `data/account.ts` حالا `points` دارد (`1,840` پایه) و `ContributionsProvider` جمع تأییدشده‌ها را رویش می‌گذارد؛ پاپ‌آور پروفایل موجودی + تعداد در انتظار را نشان می‌دهد و پنل «Your contributions» همهٔ ارسال‌ها را با وضعیت (Pending review / Approved / Sent back)، تعداد خط، زبان و زمان ارسال لیست می‌کند.
- **نمونهٔ آماده:** `COMMUNITY_LYRICS.sm1` یک شیت تأییدشده برای «Slow Motion» (آلبوم LUNEX) است تا حلقهٔ کامل — از پنل خالی تا اعتبار بنفش و امتیاز — بدون هیچ کلیکی دیده شود. سه ترک `pb1` / `le1` / `sm1` در `QUEUE` همان «برش‌های آلبومی» هستند که شیت تحریریه ندارند.

| `src/data/lyrics.ts` | لیریک تحریریه + `LYRIC_REWARD` · `COMMUNITY_LYRICS` · `parseSubmission` · `submissionProblem` · تایپ `LyricSubmission` |

## فروشگاه (`#/shop`)

پنجمین مقصد منوی اصلی: **ویترین** مرچ کی‌پاپ — هودی، کفش، دستبند، فوتوکارت، لایت‌استیک،

هزارگان قالب‌بندی می‌شوند، و هیچ سبد/پرداختی داخل اپ وجود ندارد — خرید همان‌جا انجام می‌شود
و خط زیر تیتر همین را به کاربر می‌گوید. اسکرول عمودی هم داخل کارت محتوا انجام می‌شود.
داده و عکس‌ها: `src/data/shop.ts` و `src/assets/photos/shop/` (۱۸ عکس ۶۴۰×۶۴۰).

## کارت لیست آهنگ‌ها (آلبوم / آرتیست / پلی‌لیست)

هدر کارت جزئیات سه بلوک هم‌ردیف دارد: بازگشت + کاور، بعد **نام با مشخصاتش زیر آن**
(سازنده در خط اول، و `سال · تعداد آهنگ · مدت` در خط دوم) و **کنترل‌ها در سمت مقابل
مشخصات** — نه زیر نام. هر کنترل یک `ExpandPill` است: در حالت عادی فقط آیکن، و با هاور
(یا focus، و در موبایل همیشه) واژه‌اش باز می‌شود — پخش همه، تصادفی، اشتراک و (برای
پلی‌لیست خودت) ویرایش.

صفحهٔ آرتیست دو بخش دارد: **سینگل‌ترک‌ها** و **آلبوم‌های آرتیست**؛ ردیف هر آلبوم خودش را
داخل همان کارت باز می‌کند (و دکمهٔ پخش روی هاور، همان آلبوم را پلی می‌کند).

## صفحهٔ «Get the app» (`#/download`)

مقصد دکمهٔ دانلود: کارت هیرو با آیکون اپ + دکمه‌های `Google Play` / `Download APK`، توضیح اینکه وب فقط استریم می‌کند و ذخیرهٔ آفلاین مخصوص اندروید است، و چهار کارت ویژگی (Offline saves / Hi-res masters / Background play / Live lyrics). این صفحه در منو نیست و از `contextualRoutes` می‌آید — مثل `News`.
در سندباکس/دمو، دکمه‌های استور فقط توست می‌دهند که این یک پروتوتایپ است.

## تصاویر
- **عکس واقعی self-hosted** در `src/assets/photos/`: ۸ آرتیست (۲۸۰px)، ۱۳ کاور آلبوم/سینگل (۴۲۰px)، ۶ پلی‌لیست، ۱۳ آواتار شنونده/پیام/پروفایل (۱۶۰px) و ۳ بنر ۱۴۰۰×۴۶۰ — جمعاً ۶۱ فایل WebP و ~۱.۳MB (شامل ۱۸ عکس محصول فروشگاه)، همه با گرید رنگی برند یکدست شده‌اند.
- بدون هیچ درخواست تصویر به بیرون؛ `build.assetsInlineLimit = 2048` تا هر عکس فایل جدا و cacheable بماند.
- `Cover`/`ArtistCover`/`Avatar` پراپ `src` می‌گیرند و در نبود عکس، همان هنر تولیدشده با `seed` را می‌کشند (fallback).
- کارت‌های خبر عمداً تصویرسازی‌شده مانده‌اند؛ رستر مشترک آرتیست/آلبوم در `src/data/library.ts` است.
- جزئیات + منابع + هشدار لایسنس: [`docs/photos.md`](docs/photos.md).

## تعامل‌ها و انیمیشن‌ها

- **بنر چرخشی:** دکمه‌های قبلی/بعدی دایره‌ای سفید با هاور بنفش، دات‌های نشانگر، پخش خودکار ۷ ثانیه‌ای با توقف روی هاور، سوایپ با درگ، کلیدهای ← →، پارالاکس تصویر با ماوس.
- **تقویم:** انتقال ستون روز فعال با `layoutId`، سوییچ تایم‌گرید/لیست، استپر ماه، کارت رویداد شناور **قابل درگ**.
- **خوش‌آمد:** تکان‌خوردن 👋، برگ‌های متحرک، اسپارکل پس از ارسال درخواست، فیلترهای سریع.
- **پیام‌ها:** تعویض مکالمه، Accept/Reject دعوت، ایندیکیتور تایپینگ، پاسخ خودکار، اسکرول خودکار.
- **کتابخانه:** هاور کارت‌ها با ظاهر شدن دکمهٔ پخش، Follow/Following، ریسپانسیو تا موبایل.
- **پلیر (کارت راست):** دکمه‌های پخش همه‌جا کارت را پر می‌کنند (شلف جدیدترین/ترند، کارت آرتیست/آلبوم)، نوار پیشرفت قابل کلیک و درگ و کلید ←/→، پخش/توقف، بعدی/قبلی (قبلی اول ترک را از ابتدا می‌خواند)، اسکرول خودکار لیریک با هایلایت خط فعال، و محوشدگی پایین ناحیهٔ لیریک. حالت خالی با 👋 و سه پیشنهاد سریع.
- **فید خانه:** اسکرول‌شو همراه بنر در ستون چپ؛ هدر چسبانِ هر شلف زیر نوار چیپ‌ها، چیپ‌های میان‌بر که با `scrollIntoView` به هر شلف می‌پرند و با اسکرول، چیپ فعال خودکار عوض می‌شود؛ شمارندهٔ **آتش** قابل کلیک با انیمیشن پاپ؛ و محوشدگی نرم پایین ستون برای اشاره به ادامهٔ محتوا.
- **دسترس‌پذیری:** احترام کامل به `prefers-reduced-motion` (هم CSS و هم Framer Motion).

## محتوای فید (K-pop)
آرتیست‌های فالو‌شده، جدیدترین آهنگ‌ها، ترندها با مقدار آتش، آخرین اخبار (با صفحهٔ `#/news`)، تازه‌ترین آلبوم‌ها و کاربران فعال با امتیاز/سطح — همه در `src/data/feed.ts`.
آهنگ‌های «جدیدترین» و «ترند» هم‌زمان صف پلیر را می‌سازند (`src/data/player.ts`) و لیریک دوزبانه‌شان در `src/data/lyrics.ts` است.
